二、A–F 研究論述（完整分析）

A. Attention Getter｜可量化的尋位痛點

駕駛要找的是抵達時仍可停放的車位。SFMTA 的 SFpark 試辦評估顯示，試辦區平日 09:00–18:00 自陳尋位時間由 11 分 36 秒降為 6 分 36 秒，下降 43%；對照區則下降 13%。這項舊金山「停車資訊＋需求反應定價」整體案例直接呈現尋位成本，但不能推論新北有相同尋位時間，也不能將改善歸因於本專題或 AI。研究因此聚焦「查詢時有位，抵達時是否仍有位」，而非宏觀市場規模。S1

B. But｜從尋位成本接到決策缺口

即時車位顯示只能描述觀測當下；在行車期間，需求變動、資料延遲與來源故障可能使建議失效。Cao 等人的路邊停車研究亦討論不準確預測把駕駛導向已占用車位、延長搜尋的問題。現有研究已涵蓋時空預測與不確定性，因此本專題的缺口是：在新北路邊情境中，預測、資料品質與失敗處理是否共同改善抵達決策，須以同條件基準驗證，而非宣稱首創停車預測。6 11

C. Cure｜主動取數、分析與決策的 Agent

規劃智慧停車 AI Agent：接收目的地、抵達時間與步行限制後，Planner 自動選工具、擷取資料、檢查品質、呼叫預測與排序工具，再輸出含來源時間、依據及限制的 Top-k 建議。來源逾時或失效時有界重試／重規劃；證據不足則退回合法基準、要求確認或棄權。語言互動負責理解與協調，車位數與風險依工具結果產生；新北整合服務仍為規劃。原始設計 §1–6

D. Development｜三類具體方法與工作流

方法分為三類：（1）情境與資料取得：Planner 選擇 HTTP JSON Connector／歷史 JSONL，檢查 schema、來源時間、缺值及容量。（2）時間預測與風險分析：以 past-only lag／rolling 特徵比較 Persistence、同星期同時段 Historical Median、Random Forest、HistGradientBoosting；規劃以 Isotonic／Platt scaling 校準，未驗證前不把品質分數當滿位機率。（3）決策與自主調度：先套用停車類型／步行限制，再以距離、經驗證的滿位風險及各候選自身品質作規則排序，並透過 Tool Registry＋Planner 執行有界 Retry／Replan／Abstain、保存 Evidence Log。GIS 呈現參照來源中臺中原型的 React／TypeScript／Leaflet 與 FastAPI，新北尚未整合；Haversine 僅為直線距離估計。六步工作流及失敗分支統一見 AGENT_WORKFLOW.md。原始設計 §3–6、§10、§12–13

E. Experiments｜與假設一一對應的驗證

規劃依時間順序 60／20／20 切分，排除目標時間跨切分邊界的樣本，僅使用 cutoff 前可得特徵。H1 在共用 test rows 與 +30／+60 分鐘 horizon 比較模型及 Persistence 的 MAE／RMSE；H2 在相同步行限制及接受請求覆蓋率下，比較風險排序與距離排序的抵達 Top-3 Success、Brier／ECE 與棄權率；H3 以相同工具及 timeout／stale／schema error 故障，比較 Agent 與固定 Pipeline 的無證據建議、coverage 及 p95 延遲。MAE 改善至少 5%、滿位 Recall ≥0.80、Top-3 改善至少 5 個百分點、p95 ≤3 秒均為待驗證門檻。評估規劃

F. Findings｜已知證據、預期貢獻與限制

來源 DESIGN.md 記載新北 Phase 2 在同一批 9,178,935 筆測試觀測上的 MAE：Persistence 0.326757、Random Forest 0.402669、HistGradientBoosting 0.537539。這項整體比較不支持樹模型優於 Persistence，且有跨切分標籤與觀測涵蓋限制，需修正後重驗。本庫未附重跑資料與程式；原提案抽樣 MAE 約 7.12 格是另一實驗，不作前後改善比較。H2／H3 與抵達推薦效益尚未驗證。預期貢獻是可追溯、可棄權且可被實驗否證的抵達決策流程；臺中資訊型原型及 Birmingham 路外資料不等同新北服務已完成。原始設計 §10–15 城市與階段界線

三、Agent Workflow｜逐步運作與失敗處理

規劃流程：① 目的地／抵達時間／步行限制 → ② Planner 自動選工具、取得 JSONL／API → ③ Schema／時效／容量檢查 → ④ cutoff 前特徵、模型或合法基準 → ⑤ 風險與距離規則排序、附候選證據 → ⑥ Top-3 建議及抵達核對。

失敗分支：品質檢查失敗 → 在次數上限內 Retry／Replan → 回到資料取得；仍無足夠證據則 Abstain。沒有有效資料時，不用過期基準冒充可信預測。H3 使用相同來源、工具、模型、故障與計算預算，對照固定 Pipeline。

四、5 Core Mindsets／3 Trade-offs／10 Deep Questions

Five Core Mindsets｜五大核心思維

  1. 資料品質先於模型：先驗證 schema、觀測時間、路段識別、缺漏與容量。
  2. 模型與預測時距一致：區分 +30／+60 分鐘目標及合法標籤。
  3. 保留停車營運語意：路邊與路外、不同城市與路段不可混算。
  4. 先超越簡單 Baseline：以 Persistence 為必要基準，接受複雜模型不勝出的結果。
  5. 不確定性必須影響決策：結合來源新鮮度、風險校準、推薦涵蓋與棄權。

Three Trade-offs｜三項研究爭議

  1. 簡單模型 vs. 深度時空模型：準確度、資料量、可解釋性與部署成本的取捨。
  2. 共用路段模型 vs. 個別路段模型：樣本效率、地區差異與泛化能力的取捨。
  3. 點預測 vs. 風險感知 Top-k：平均誤差、滿位風險與使用者抵達成功率的取捨。

Ten Deep Questions｜十大驗證問題

  1. 為何抵達時間可用性比即時剩餘格數更符合駕駛決策？
  2. 新北歷史 JSONL 的路段涵蓋、時間間隔及缺漏是否足以訓練？
  3. API timeout、stale 或 schema error 時 Agent 如何 Replan？
  4. 近距離高滿位風險與遠距離低風險路段如何權衡？
  5. 錯誤狀態與重複主鍵如何影響觀測聚合？
  6. Agent 相較固定 Pipeline 是否實際改善有證據的推薦？
  7. 如何防止特徵 cutoff 與未來標籤跨切分邊界洩漏？
  8. Birmingham／臺中哪些方法可移轉，哪些結果不可移轉？
  9. 如何以抵達後容許窗內的合法觀測建立 Ground Truth？
  10. 哪些校準、Top-k、涵蓋率與延遲條件構成 Go／No-Go？

六、IEEE Transactions 風格英文 Abstract

Title—An Uncertainty-Aware AI Agent for Arrival-Time Parking Availability Prediction and Risk-Aware Recommendation

Abstract—In San Francisco's SFpark pilot areas, reported parking-search time fell from 11 minutes 36 seconds to 6 minutes 36 seconds, a 43% decrease, under a combined information and pricing program. This external case motivates attention to search costs; it is not an outcome of the proposed system. A vacancy observed at query time may disappear before arrival, while delayed observations and source failures further complicate guidance. This study proposes an evidence-aware smart parking agent for roadside segments in New Taipei City, Taiwan. Its workflow autonomously collects source data, validates schema, freshness and capacity, compares Persistence, Historical Median, Random Forest and HistGradientBoosting, and produces arrival-time Top-k recommendations with candidate-specific evidence. A planner coordinates tool selection, bounded retry, replanning and abstention rather than asking a language model to invent availability. A chronological 60/20/20 evaluation with purged cross-boundary targets is planned to assess prediction error, fullness-risk calibration, arrival-time Top-3 success, coverage and fault handling against matched baselines and a fixed pipeline. A separate source design reports offline MAEs of 0.3268 for Persistence, 0.4027 for Random Forest and 0.5375 for HistGradientBoosting. These results favor Persistence in that aggregate comparison, are not independently reproduced in this repository, and require corrected temporal-boundary validation. Arrival-time recommendation benefits and agent superiority remain unverified. The intended contribution is a falsifiable integration of data provenance, decision-time risk assessment and failure-aware orchestration, with explicit limits on unsupported recommendations.

Index Terms—Smart parking, arrival-time prediction, AI agent, data quality, uncertainty-aware recommendation, intelligent transportation systems.
