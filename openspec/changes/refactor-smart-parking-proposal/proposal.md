# Change Proposal: Smart Parking Research Proposal Refactor

## Why

The DIC3 project requires a specification-driven, source-traceable academic revision that clearly separates research questions, supporting literature, completed evidence and future experiments. A concise OpenSpec change makes the revised Introduction, Related Work and research argument reviewable.

## What Changes

- Preserve the original New Taipei proposal DOCX/PPTX, DESIGN.md, analysis PDF and README baseline.
- Refactor the A–F abstract, five mindsets, three controversies, ten deep questions, Introduction and Related Work.
- Compare all original references [5]–[13] with source-supported methodological boundaries.
- Separate New Taipei roadside arrival-time research, New Taipei Phase 2 offline results and Taichung information-only Agent.
- Define falsifiable H1–H3 and time-safe evaluation protocols, distinguishing source-reported results from verified experiments.
- Publish Before/After evidence, manual scenario verification and acceptance status.

## Capabilities

### New Capabilities
- `research-proposal-refactor`: traceable academic proposal documents and explicit evidence-state handling.

### Modified Capabilities
- None.

## Impact

Changes apply to documentation, OpenSpec specifications, research summaries and acceptance reports. Original evidence files remain unchanged. No production parking service or model is modified by this change.

## Success criteria

- All nine documentary Requirement/Scenario checks have traceable source evidence.
- A–F and 5/3/10 are complete, and Introduction/Related Work are academic and source-aligned.
- H1, H2 and H3 claims use appropriate evidence states; New Taipei and Taichung outcomes are not conflated.
- Manual validation is accurately labeled, with native OpenSpec CLI and unrun experiments excluded from PASS claims.
